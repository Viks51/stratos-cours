2.1.1 Qu’est-ce qu’une base de données ?

A savoir

Imaginez que vous gérez une bibliothèque avec des milliers de livres. Vous pourriez les empiler en vrac dans une pièce, mais ce serait le chaos ! Impossible de retrouver un livre rapidement. Alors vous les rangez dans des étagères, par catégories, avec un système de classement. Eh bien, une base de données, c’est exactement ça, mais pour les données informatiques.

Définition

  • Une base de données (ou BDD), c’est un système organisé qui permet de :
    • Stocker de grandes quantités d’informations ;
    • Organiser ces informations de manière structurée ;
    • Retrouver facilement et rapidement ce qu’on cherche ;
    • Modifier ou supprimer des données quand c’est nécessaire.

Exemples

  • Vous utilisez des bases de données tous les jours sans le savoir :
    • Netflix : stocke vos films, séries, vos préférences ;
    • Facebook/Instagram : vos profils, photos, amis, messages ;
    • Amazon : produits, commandes, clients, stocks ;
    • Le campus : notes, emplois du temps, informations des étudiants.

Organisation

  • Prenons l’exemple d’une base de données pour un site e-commerce : Table CLIENTS

Les principaux acteurs

  • Pour travailler avec une base de données, on a besoin de :
    • Le SGBD (Système de Gestion de Base de Données) : c’est le logiciel qui gère tout (exemples : MySQL, PostgreSQL, Oracle, MongoDB, etc.) ;
    • Le langage SQL : pour communiquer avec la base (SELECT, INSERT, UPDATE, DELETE, etc.) ;
    • L’application : votre site web ou logiciel qui interroge la base.

A retenir

Une base de données, c’est :

  • Un entrepôt organisé pour vos données ;
  • Rapide pour chercher et récupérer l’info ;
  • Sécurisé et fiable ;
  • Structuré avec des relations entre les données ;
  • Indispensable pour toute application moderne.

2.1.2 L’organisation des données

Le rôle et le fonctionnement des bases de données

  • Une organisation doit pouvoir conserver de façon structurée les informations utiles aux différents traitements des processus ;
  • Les bases de données relationnelles (BDR), épines dorsales des SI actuels, jouent ce rôle et mémorisent les informations qui y sont décomposées, organisées sous forme de données et stockées ;
  • Il est donc possible de compléter, de modiﬁer, d’interroger et d’exploiter ces données en fonction des besoins des utilisateurs.

Définition

Le système de gestion de base de données relationnelle (SGBDR) prend en charge différentes bases de données qui interagissent.

La collecte et la sélection des données

Les objectifs de la collecte
  • Il est inutile de stocker, dans une base de données, des informations qui ne seront pas mises en œuvre dans un processus ou qui n’interviendront pas dans un traitement ;
  • Il faut donc choisir les données utiles en réalisant des entretiens, en analysant des documents ;
  • Le travail d’analyse peut mettre en évidence des ambiguïtés à traiter par :
    • L’individualisation des polysèmes (données qui ont le même nom mais pas la même signiﬁcation) en attribuant deux libellés différents ;
    • La conservation d’une donnée pour les synonymes (données qui ont la même signiﬁcation mais des noms différents dans plusieurs documents).

A savoir

Le recensement des règles de gestion pour l’obtention des données calculées est important : il permet de vous assurer que vous n’oubliez pas de données élémentaires. Vous pouvez éventuellement choisir de conserver une donnée calculée pour répondre à un impératif de gestion.

Exemple

Le code du client et celui du fournisseur ne peuvent être tous deux référencés par le nom « Code ». La référence et le code d’un produit représentent la même donnée que l’on peut nommer « référence_produit ». Les données doivent être élémentaires : elles doivent être utiles en l’état, sans être scindées et ne pas résulter d’un calcul à intégrer à un traitement.

Exemple

Une adresse est le plus souvent séparée en trois éléments, l’adresse_rue (10 rue Amiral Courbet), l’adresse_ville (LORIENT) et le code_postal (56100). Le montant TTC d’un produit peut être retrouvé en appliquant un taux de TVA au montant HT. Ce taux ne sera pas conservé.

Le recueil des informations et l’élaboration du dictionnaire des données

Définitions

  • Un dictionnaire des données est un document qui regroupe les données élémentaires et constitue donc un référentiel pour élaborer la base, il la décrit ;
  • Un paramètre est une donnée susceptible d’intervenir dans les calculs, dont la valeur est stable (à moyen terme) et unique.
  • Les paramètres peuvent être clairement identiﬁés dans le dictionnaire alors que les constantes (données permanentes) ne le sont pas.

Exemple

Le dictionnaire reprend le taux de TVA (paramètre) mais pas l’adresse de l’entreprise ou sa désignation (constantes).

  • Forme
    • Le dictionnaire des données prend le plus souvent la forme d’un tableau à quatre colonnes contenant le nom, le code et le type de donnée ainsi que d’éventuels commentaires ;
    • Le type décrit la nature des valeurs associées à une donnée ;
    • Plusieurs typologies existent, il conviendra a minima de différencier les types numériques (réels, entiers, monétaires, dates…), alphabétiques (ou alphanumériques) et booléens (logiques).
  • Établissement du dictionnaire
    • Il est créé en respectant trois étapes :
      • Le recensement des données. Il consiste à attribuer à chaque donnée un code et un nom signiﬁcatif ;
      • L’indication du type de chaque donnée et de la règle de calcul éventuelle ou de toute autre observation utile ;
      • La sélection des données élémentaires par la résolution des ambiguïtés éventuelles et la suppression des données calculées et des paramètres.

La structuration des données

Les objectifs de la structuration
  • Les données élémentaires doivent être organisées pour être traitées aisément ;
  • Cette organisation doit être pertinente et mettre en évidence les liens entre les données pour obtenir les informations nécessaires à l’organisation ;
  • Elles forment ensemble, quand elles se complètent, des objets matériels ou immatériels du système d’information ;
  • L’utilisation d’une structure de données appropriée simpliﬁe les bases qui en découlent, ce qui contribue à supprimer les erreurs et anomalies ;
  • La future base, ainsi structurée, pourra alors traiter les données automatiquement de façon rapide et efﬁcace.
Les attributs

Définition

Un attribut correspond au plus petit élément d’information manipulable.

  • Un nom d’attribut permet de décrire les données élémentaires, elles prennent alors des valeurs et un sens dans le système d’information (SI) étudié ;
  • L’organisation des attributs permet donc de structurer les données.

Exemple

L’attribut « Nomcli » prend diverses valeurs comme ici « Huet », il caractérise le client et a donc une signiﬁcation dans le SI de l’entreprise Magadur.

  • L’ensemble des valeurs possibles pour un attribut représente le domaine de valeurs.
Les dépendances fonctionnelles
  • Pourquoi parler de dépendances fonctionnelles ?
    • Imaginez une base de données comme un tableau Excel géant où vous stockez des informations sur vos clients, vos produits ou vos commandes. Pour que cette base soit fiable et facile à utiliser, il faut organiser les données de manière logique ;
    • Les dépendances fonctionnelles (DF) sont des règles qui permettent de :
      • Éviter les redondances (ex. : répéter 10 fois l’adresse d’un même client) ;
      • Garantir la cohérence (ex. : si le code postal change, il doit être mis à jour partout) ;
      • Optimiser la structure de la base pour des requêtes plus rapides.

Définition

Une dépendances fonctionnelle est une relation entre deux attributs (colonnes) d’une table. On note : X → Y (se lit “X détermine Y” ou “Y dépend fonctionnellement de X”).

Exemple

Prenons une table Clients avec les colonnes :

  • N°Client (ex. : C001, C002)
  • Nom (ex. : Dupont, Martin)
  • Ville (ex. : Paris, Lyon) Ici, N°Client → Nom :
  • Si je connais le N°Client (ex. : C001), je peux trouver un seul Nom associé (ex. : Dupont).
  • À l’inverse, Nom → N°Client n’est pas valide : deux clients peuvent s’appeler “Dupont” !
  • Règles clés à retenir
    • Pour qu’une dépendance X → Y soit valide :
      1. Unicité : à chaque valeur de X correspond une seule valeur de Y (pas d’ambiguïté).
      • Exemple valide : N°Client → Ville (un client a une seule ville) ;
      • Exemple invalide : Ville → N°Client (une ville peut avoir plusieurs clients).
      1. Stabilité dans le temps : la relation doit toujours être vraie, même si les données changent.
      • *Exemple *: CodePostal → Ville est généralement stable (un code postal = une ville).
      1. Minimalité : X doit être le plus petit ensemble possible pour déterminer Y.
      • *Exemple *: si N°Client + Nom → Ville mais que N°Client → Ville suffit, la première DF n’est pas minimale.
  • A quoi ça sert ?
    • Les dépendances fonctionnelles sont utilisées pour normaliser une base de données, c’est-à-dire l’organiser en tables sans anomalies ;

Exemple

  • Redondance : “Dupont” et “Paris” sont répétés pour chaque commande du client C001 ;
  • Risque d’incohérence : si Dupont déménage à Marseille, il faut modifier toutes ses lignes. Solution : appliquer les DF :
  1. On identifie les DF :
  • N°Client → NomClient, VilleClient (un client a un nom et une ville uniques) ;

  • Plus de redondance ;
  • Mise à jour facile (ex. : changer la ville de Dupont en une seule fois).

2.1.3 Le modèle relationnel

Les grands principes

Définitions

  • Un modèle est une simpliﬁcation de la réalité qui facilite sa compréhension. Le modèle doit être clair, rigoureux et aisément interprétable ; il intègre les éléments fondamentaux qui expliquent un phénomène ou une situation ;
  • Développé par l’informaticien britannique Edgar Frank Codd (1923-2003), le modèle relationnel représente l’ensemble des relations d’un système d’information.
  • Le modèle relationnel peut être élaboré à partir du graphe des dépendances fonctionnelles.
Les relations
  • Un ensemble d’attributs ayant la même source de dépendance fonctionnelle, et donc associés de façon signiﬁcative, constitue une relation ;
  • Élément du système d’information, une relation peut être représentée par un tableau à deux dimensions ou par un schéma relationnel ;
  • L’attribut source de dépendance fonctionnelle est appelé « clé primaire » ; il est positionné en première position et souligné dans la présentation schématique ;
  • Représentation sous forme de tableau :
    • Le tableau comporte un nombre non déﬁni de colonnes qui correspondent, chacune, à un attribut, chacun étant associé à un nom unique ;
    • Chaque ligne du tableau est un tuple ou n-uplet, c’est-à-dire une occurrence de valeurs d’attribut ;
    • Une valeur de clé primaire permet d’identiﬁer, de façon certaine, le tuple correspondant, sachant qu’elle est unique.
    Exemple Relation PRODUIT

…
  • Représentation sous forme de schéma :
    • Le schéma est composé du nom de la relation, suivi de la liste des attributs qui la composent.

Exemple

Le schéma de la relation précédente devient, en notation fonctionnelle : PRODUIT (RefProd, Désignation, PUHT)

  • Si la clé primaire d’une relation est en dépendance fonctionnelle avec la clé primaire d’une autre relation, la clé primaire « BUT » devient une clé étrangère dans la relation dont la clé primaire est la « SOURCE » de la dépendance fonctionnelle ;
  • Chaque clé étrangère est le plus souvent signalée par un dièse (#) ;
  • Elle est reprise dans la relation SOURCE, généralement à la suite des autres attributs.

Exemple

Les caractéristiques du modèle relationnel
  • Le modèle relationnel regroupe toutes les relations du système d’information étudié ;
  • Il possède diverses caractéristiques et contraintes :
    • Le nom de chaque relation est unique ;
    • Le degré de la relation représente son nombre d’attributs ;
  • Une relation répond à différentes contraintes :
    • Elle possède une clé dite primaire qui permet d’identiﬁer les différents tuples, celle-ci peut correspondre à un seul attribut ou être composée de plusieurs attributs (concaténés) ;
    • Chaque tuple est unique ;
    • Aucune clé primaire ne peut être nulle.
  • Toutes les relations doivent être liées, c’est le rôle des clés étrangères.

Les formes normales
  • Les formes normales sont des règles pour organiser les tables et éviter les anomalies ;
  • Elles s’appuient sur les dépendances fonctionnelles.

    • Règle :
      • Chaque colonne doit contenir une seule valeur (pas de listes ou de valeurs multiples) ;
      • Chaque ligne doit être unique (identifiée par une clé primaire).

2.1.4 Le modèle relationnel — exposition à fusionner

Définition

  • Le modèle relationnel, c’est une méthode d’organisation des données inventée en 1970 par Edgar Frank Codd (un informaticien chez IBM) ;
  • L’idée principale ? Organiser les données dans des tables et créer des relations entre ces tables.

Les 3 concepts de base

  1. Les tables (ou relations)
  • Une table, c’est comme un tableau avec :
    • Des lignes (appelées tuples ou enregistrements) : 1 ligne = 1 entité ;
    • Des colonnes (appelées attributs ou champs) : les caractéristiques.
    Exemple : table ETUDIANTS
ID_EtudiantNomPrenomDate_NaissanceClasse
1DuboisJulie12/03/2004ENGDE 1
2MercierThomas25/07/2003ENGDE 1
3BernardLisa18/11/2004ENGDE 2
  1. Les clés
  • La clé primaire :
    • C’est l’identifiant unique de chaque ligne. Pas de doublon possible !
    • Dans notre table ETUDIANTS, c’est ID_Etudiant. Deux étudiants peuvent avoir le même nom, mais jamais le même ID.
  • La clé étrangère :
    • C’est une colonne qui fait référence à la clé primaire d’une autre table. C’est elle qui crée les relations entre les tables.
  1. Les relations

  • C’est le cœur du modèle ! Les tables ne sont pas isolées, elles communiquent entre elles.

    Exemple : un système scolaire ❌ MAUVAISE approche (tout dans une table)

    • Répétition des noms (redondance) ;
    • Si Julie change de nom → modifier plein de lignes ;

Les types de relations

  • Relation 1:n (Un vers Plusieurs)
    • Un étudiant peut avoir plusieurs notes, mais une note appartient à un seul étudiant ;
    • ETUDIANTS (1) ----< (N) NOTES
  • Relation n:n (Plusieurs vers Plusieurs)
    • Plusieurs étudiants peuvent suivre plusieurs matières ;
    • ETUDIANTS (N) ----< INSCRIPTIONS >---- (M) MATIERES
    • On crée alors une table intermédiaire (table de liaison).
  • Relation 1:1 (Un vers Un)
    • Un étudiant a un seul dossier médical, et un dossier appartient à un seul étudiant ;
    • ETUDIANTS (1) ---- (1) DOSSIERS_MEDICAUX

Les règles

  • Pour qu’une base soit bien conçue, elle doit respecter certaines règles :
    • Chaque table a une clé primaire unique ;
    • Pas de valeurs multiples dans une cellule :
      • “Math, Info, Anglais” dans une seule case ;
      • Une ligne par matière.
  • Pas de répétition de groupes de colonnes :
    • Note1, Note2, Note3… ;
    • Une table NOTES séparée.

2.2.2 Gérer les attributs non renseignés

Définition

      • la création de lignes ;
      • la lecture de lignes ;
      • l’actualisation de lignes ;
      • la suppression de lignes.

Les types d’associations
  • À ce stade, vous savez qu’une clé étrangère sert à créer une association entre une table A et une table B ;
  • Voyons maintenant les 3 cas de figure dans lesquels on les utilise :
    • L’association un-à-un ;
    • L’association un-à-plusieurs ;
    • L’association plusieurs-à-plusieurs.
  • En fait, tout est question du nombre de lignes de A qui peuvent être associées aux lignes de B, et inversement !

Implémentez une association plusieurs-à-plusieurs
  • Passons maintenant au cas de l’association plusieurs-à-plusieurs ;
  • C’est quand une ligne d’une première table peut être associée à plusieurs lignes d’une seconde table, et qu’une ligne de cette seconde table peut être associée à plusieurs lignes de la première table ;

  • Une association un-à-plusieurs se traduit en ajoutant une clé étrangère dans la table qui est du côté « plusieurs ». Cette clé étrangère référence la clé primaire de la table qui est du côté « un » ;
  • Une association plusieurs-à-plusieurs se traduit en ajoutant une nouvelle table. La clé primaire de cette nouvelle table sera composée (au moins) des deux clés étrangères référençant les deux tables à associer.

A savoir

WHERE permet de filtrer les lignes d’une table selon un certain critère.

  • Comme les lignes à garder (ou enlever) sont dynamiques, il nous faut donc établir une condition qui nous permette de filtrer les lignes voulues.

Ici, fk signifie clé étrangère, et pk clé primaire.

SELECT * FROM t1, t2 WHERE (t1.fk1 = t2.pk1 AND t1.fk2 = t2.pk2); - Seconde syntaxe : sql SELECT * FROM t1 JOIN t2 ON (t1.fk1 = t2.pk1 AND t1.fk2 = t2.pk2); ```

SELECT * FROM entity LEFT OUTER JOIN address ON entity.id_address = address.id_address; - Si au contraire, nous voulons garder *toutes* les adresses (qu'elles correspondent à une société ou non), il faut alors faire une jointure **externe à droite** : sql SELECT * FROM entity RIGHT OUTER JOIN address ON entity.id_address = address.id_address; ```

Bien entendu, une jointure externe à droite est équivalente à une jointure externe à gauche pour laquelle on aurait interverti entity  et address . Certains SGBDR n’acceptent d’ailleurs que l’une de ces deux jointures : c’est alors à vous d’intervertir les tables !

        ```sql

SELECT * FROM entity FULL OUTER JOIN address ON entity.id_address = address.id_address; ```

Partitionnez vos données
  • Pour illustrer cette partie, reprenons les Panama Papers.

A savoir

Souvent, les mots juridiction et pays sont synonymes, car en général, les lois sont les mêmes à l’intérieur d’un même pays.   • Voici un aperçu de ces colonnes :
  • Si je choisis de partitionner les sociétés par juridiction, cela signifie que je veux former des groupes de sociétés, tels que toutes les sociétés d’un même groupe doivent être de la même juridiction.  On appelle ces groupes des agrégats.

A savoir

Plus formellement, le partitionnement a pour but de créer des groupes de lignes de manière à ce que deux lignes se trouvant dans un même groupe aient les mêmes valeurs pour les colonnes de partitionnement.

  • Je peux également partitionner sur plusieurs colonnes. Par exemple, je peux partitionner mes sociétés par les colonnes jurisdiction et status. Ainsi, au sein d’un même groupe de sociétés, la juridiction et le statut seront identiques :

Appliquez des fonctions d’agrégation
  • Une fois les agrégats formés, il faut bien en faire quelque chose !
  • C’est là qu’intervient la fonction d’agrégation. Son rôle est de prendre en entrée un groupe de plusieurs lignes, d’effectuer un calcul sur celles-ci, puis de retourner *une unique valeur pour chacun des groupes *;
  • Parmi les fonctions d’agrégation, on peut trouver la moyenne, le minimum, le maximum, la somme, etc.
  • Par exemple, on peut appliquer la fonction qui calculera la moyenne des durées de vie des sociétés (lifetime). On l’applique d’abord au groupe des sociétés de la juridiction ANG et du statut “In transition”,  puis au groupe des sociétés de ANG ayant le statut “Dissolved”, etc.
  • En général, une fonction d’agrégation prend en entrée une liste et renvoie une unique valeur ;
  • Par exemple, pour calculer la durée de vie moyenne des sociétés, la fonction moyenne prendra en entrée la liste des durées de vie des sociétés de l’agrégat, et retournera la moyenne de cette liste. C’est ce qui se passe sur l’image ci-dessus.

Déterminez la clé primaire après une agrégation
  • Vous vous souvenez, lors d’un précédent chapitre, nous avions dit qu’il est très important de connaître la potentielle clé primaire d’une table ! Je vous propose ici un petit raisonnement pour trouver la clé primaire d’une table issue d’une agrégation.

A savoir

Comme la fonction d’agrégation retourne une valeur pour chacun des agrégats, la table qui résultera de l’agrégation aura autant de lignes que d’agrégats.

  • La nature des objets représentés par une ligne avant l’agrégation (ici : une société) ne sera pas la même qu’une ligne après agrégation (ici : un ensemble de sociétés) ;
  • Si la nature des lignes a changé, alors la clé primaire a probablement aussi changé !
  • Mais heureusement, c’est assez simple. Comme on groupe par status  et jurisdiction  , alors il ne peut pas y avoir (dans le résultat) 2 lignes qui ont à la fois le même statut et la même juridiction (bah oui, sinon elles auraient été regroupées en une !). Il y a donc bien unicité, et on peut prendre comme clé primaire [status, jurisdiction]  !

A savoir

La clé primaire du résultat d’une agrégation est composée des colonnes de partitionnement. Parfois, cette clé est simplifiable.

Filtrez vos données agrégées avec HAVING

Introduction
  • La clause SQL HAVING est généralement utilisée avec la clause GROUP BY pour filtrer des groupes de lignes retournées ;
  • Les lignes ne sont incluses dans le groupe que si la condition spécifiée est VRAIE ;
  • La clause SQL GROUP BY organise les données en groupes sur la base d’une ou de plusieurs valeurs communes ; elle est le plus souvent utilisée pour obtenir des informations récapitulatives et calculer des statistiques agrégées ;

Introduction
  • La commande UNION permet de mettre bout-à-bout les résultats de plusieurs requêtes utilisant elles-même la commande SELECT ;

2.4.1 Le fonctionnement général du tableur

Introduction

Définition

Le tableur est un progiciel-outil, donc un ensemble cohérent de programmes qu’un utilisateur peut activer selon ses besoins en s’appuyant sur une documentation.

  • Conçu initialement pour effectuer des calculs complexes, le tableur offre de nombreuses fonctionnalités complémentaires utiles au gestionnaire (traitement de textes courts, construction de graphiques et moyens de simulation notamment).

Une première approche du tableur

  • Le tableur gère des feuilles de calcul (des tableaux à deux dimensions) composées de cellules (intersections d’une ligne et d’une colonne) où sont rangées des informations ;
  • Une cellule peut contenir du texte, des images, des valeurs numériques ou des formules ;
  • Les feuilles de calcul sont regroupées dans des classeurs, chaque classeur contenant des feuilles liées entre elles.

Les composantes d’une feuille de calcul Excel

  • Une feuille de calcul présente principalement trois zones :
    • Un quadrillage représentant les cellules de la feuille, où sont placés données et calculs ;
    • Une ligne d’édition, sur laquelle apparaît le détail du contenu de la cellule active à un moment donné (y ﬁgurent également les cadres permettant de nommer la cellule ou d’y déﬁnir une fonction standard de calcul) ;
    • Un bandeau regroupant les menus donnant accès aux fonctionnalités du tableur.

2.4.2 Les formules de calcul

Introduction

  • Tout traitement contenu dans la feuille de calcul nécessite de sélectionner la ou les cellules concernées puis de choisir l’action à effectuer ;
  • Une cellule est repérée par ses coordonnées (ligne et colonne). Une plage de cellules est délimitée par les coordonnées de ses cellules extrêmes.

Exemple

« Cellule B5, plage C2:D10 » correspond aux cellules C2, C3,… C10, D2, D3,…, D10.

Les formules de calcul

  • L’expression de la formule de calcul placée dans une cellule commence toujours par le signe « = » ;
  • Elle fait généralement appel à des opérateurs arithmétiques (« + », « – », « * » pour la multiplication, « / » pour la division, « ^ » pour l’élévation à une puissance) ;
  • Les formules de calcul peuvent faire référence à d’autres cellules de la feuille (sauf quand elles servent à initialiser une valeur, par exemple en y recopiant le contenu d’une autre cellule) ;
  • Elles peuvent intégrer des fonctions qui, elles-mêmes, comprennent du texte et des symboles spéciaux ou de comparaison (« = », « < » « > » et « <> » pour différent).

Exemple

  • « =A2*5 », effectue la multiplication de la valeur de la cellule A2 par 5
  • « =C8 » correspond à la reprise de la valeur placée en « C8 »
  • « =SOMME (C10:C12) » fait référence à une fonction qui calcule C10+C11+C12 (la somme des valeurs des cellules comprises entre C10 et C12, donc dans la plage « C10:C12 »).
  • La formule saisie dans une cellule est afﬁchée dans la ligne d’édition en haut de l’écran, mais elle n’apparaît pas a priori dans la cellule où elle est placée, qui afﬁche directement le résultat du calcul ;
  • Toute évolution du contenu d’une cellule entraîne la modiﬁcation automatique du résultat des calculs qui y font référence.

Les modes de référence aux cellules

Les références absolues, relatives ou mixtes
  • Le contenu d’une cellule peut être recopié dans une ou plusieurs d’entre elles, notamment par les commandes « Copier-Coller » :
    • Les textes et les valeurs sont copiés sans modiﬁcation ;
    • En revanche, lors de la copie d’une formule, les références à des cellules contenues dans cette dernière sont adaptées en fonction du décalage entre la cellule d’origine et la ou les cellules de destination (translation de références).

Exemple

  • La formule en C1 fait référence de façon relative à A1 et B1 ;
  • Elle est copiée à partir de C1 et collée en C2 ;
  • Elle s’adapte par translation et C2 fera donc référence à A2 et B2.
  • Pour éviter toute modiﬁcation des formules, il faut faire précéder l’indice de ligne et/ou de colonne des cellules concernées par le symbole de référence absolue « $ » ;
    • Dans le cas précédent, une formule = A$1+B$2 saisie en C1 resterait = A$1+B$2 en C2 ;

La notion de « nom » d’une cellule ou d’une plage de cellules
  • Une cellule ou une plage de cellules peut être nommée pour y faire référence sans craindre un décalage intempestif, tout en améliorant la lisibilité des formules concernées ;
  • Le recours à des noms permet également de retrouver plus facilement les erreurs ;
  • Pour créer un nom, il est possible d’utiliser le gestionnaire de noms du menu « Formules » ou de l’implanter directement dans la zone à gauche de la zone « Fonction ».
  • La déﬁnition d’une zone nommée attribue le caractère absolu à toutes les références de la zone ;
  • Ce nom est alors utilisable à la place de la référence à la cellule ou à la plage de cellules.

Exemple

  • Dans la feuille qui précède, les sommes des cellules B8 et D8 peuvent s’écrire : « =SOMME(B3:B6) » et « =SOMME(D3:D6) ». La formule en D8 peut être obtenue par copie de B8, car il y a translation ;
  • Si la plage B3:B6 était nommée VENTES, la formule en B8 pourrait s’écrire : « =SOMME(VENTES) ». Dans ce cas, elle ne pourrait plus être recopiée en D8.
  • On peut également nommer une valeur, quand on veut y faire référence, sans l’implanter dans les formules de calcul, ce qui est particulièrement utile pour des paramètres comme le taux de TVA.

Astuce

Vous devez utiliser des références absolues, relatives ou mixtes ou avoir recours à des noms de façon performante et cohérente, tout en anticipant les recopies éventuelles.

2.4.3 Les fonctions de base

Les principes généraux

  • Des fonctions prédéﬁnies sont disponibles dans le tableur pour effectuer des traitements standardisés, des calculs statistiques ou autres opérations mathématiques ;
  • La forme générale d’une fonction est : =Nom_fonction(argument1;argument2;…)
  • Le nombre d’arguments dépend de la fonction et certains peuvent être optionnels ;

  • De la même façon, la fonction « =MOYENNE(A1:A10) » calcule la moyenne des cellules A1, A2,…, A10
  • « =AUJOURDHUI() » est une fonction sans argument, qui fournit la date du jour

2.5.1 Fonctions de recherche

Introduction

  • Les fonctions de recherche permettent de trouver la valeur d’une liste associée à une autre valeur placée dans une autre liste.

Exemple

Une catégorie (codée A, B ou C) est affectée à chaque client. À chacune des catégories de la liste A – B – C correspond un taux de remise (dans l’ordre 0, 2 ou 4 %). À partir du code de catégorie d’un client, la recherche dans la liste des codes permet de trouver le taux de remise à appliquer.

  • Les listes forment une table implantée au préalable dans la feuille de calcul active ou dans une autre feuille de calcul ;
  • Les fonctions de recherche nécessitent, en général, que la première liste dans laquelle on cherche une valeur pour lui trouver une correspondance soit triée.

Fonction RECHERCHE (forme générale)

Principe
  • La forme générale de la fonction RECHERCHE est :
    • =RECHERCHE(valeur à chercher;colonne ou ligne de recherche;colonne ou ligne de résultats) ;
    • La fonction RECHERCHE recherche une valeur dans une colonne (ou une ligne) d’un tableau et renvoie une valeur située à la même position dans la colonne (ou la ligne) qui contient les résultats.

Principe

2.5.3 Ergonomie d’une feuille de calcul

Fonctions d’informations et de gestion des erreurs

Fonctions d’information « EST »
  • Les fonctions EST sont utiles pour tester le contenu de cellules ;
  • Elles ne contiennent qu’un seul argument, obligatoire, qui est une valeur à tester ;
  • L’argument-valeur peut être :
    • Une valeur vide, c’est-à-dire une cellule qui ne contient aucune donnée ou formule et non qui n’afﬁche rien ;
    • Une erreur renvoyée par le tableur ;
    • Une valeur logique, de texte, de nombre ou une valeur de référence ou un nom s’y référant.
  • Quand la fonction EST n’est pas associée à une autre fonction elle renvoie « VRAI » ou « FAUX » ;
  • Les fonctions d’information les plus courantes sont au nombre de sept :
ESTVIDERenvoie VRAI si l’argument valeur est vide.
ESTERREURRenvoie VRAI si l’argument valeur fait référence à une valeur d’erreur.
ESTLOGIQUERenvoie VRAI si l’argument valeur fait référence à une valeur logique.
ESTNARenvoie VRAI si l’argument valeur fait référence à la valeur d’erreur n/a.
ESTNUMRenvoie VRAI si l’argument valeur représente un nombre.
ESTREFRenvoie VRAI si l’argument valeur est une référence.
ESTTEXTERenvoie VRAI si l’argument valeur se présente sous forme de texte.
  • D’autres fonctions d’information sont accessibles et documentées dans l’aide du tableur.

Exemple

L’amicale laïque utilise un tableur pour gérer ses salles de réunion. =ESTNUM(B2), implanté en C2, afﬁche VRAI si C2 contient une valeur numérique ; FAUX, dans le cas contraire. B2 contient du texte (inconnu) donc la fonction renvoie FAUX. À l’inverse, =ESTTEXTE(B2), renvoie VRAI si le contenu est du texte et donc inconnu, et FAUX dans le cas contraire.

  • Les fonctions EST sont fréquemment associées à une alternative « fonction SI » pour renvoyer un message pertinent à l’utilisateur du tableur en cas d’erreur, d’absence de saisie et/ou pour effectuer un calcul sous condition.

Exemple

2.6.1 Les tableaux, tableaux croisés dynamiques et graphiques

Les tableaux

La création du tableau
  • Les tableurs permettent de gérer et d’analyser des données connexes à l’aide de l’outil « tableaux » qu’il ne faut pas confondre avec les outils de gestion ou de validation des données ;
  • Une plage de cellules peut aisément être transformée en tableau à partir du menu « Accueil/Mettre sous forme de tableaux ». Une fois le tableau créé, différentes fonctionnalités permettent de gérer les données des lignes et des colonnes sans modiﬁer le reste de la feuille de calcul.
  • Un tableau dispose des éléments suivants :
    • Une ligne d’en-tête qui permet le ﬁltrage ou le tri de chaque colonne ;
    • Des lignes identiﬁées par des trames différentes pour mieux identiﬁer les données ;
    • Quand une formule est implantée dans une cellule, la mise sous forme de tableau permet de l’appliquer à toutes les autres cellules de la colonne qui devient donc une colonne calculée.
  • Il est également possible d’ajouter une ligne « total » en sélectionnant une cellule du tableau (onglet « Accueil/Outils de tableaux création ») ;
  • Cette ligne permet d’accéder à diverses fonctions que l’on sélectionne dans une liste (moyenne, somme, nb…) ;
  • Tant que cette option n’est pas choisie, aucun cumul n’est appliqué, à l’exception des colonnes calculées pour lesquelles la fonction « sous.total » (somme dans un tableau) est sélectionnée par défaut.
La personnalisation du tableau
  • Il est possible de personnaliser un tableau en créant une fonction ;
  • Pour redimensionner le tableau, une icône « poignée » est située dans le coin inférieur droit ;
  • Il est possible d’insérer plusieurs tableaux dans la même feuille et de gérer ainsi plusieurs groupes de données ;
  • Les références à l’intérieur du tableau sont structurées par des noms déﬁnis automatiquement et mobilisables dans des formules n’importe où dans la feuille ;
  • Il est également possible d’utiliser les fonctionnalités de validation des données dans un tableau, ce qui en garantit l’intégrité.

Exemple

La feuille de calcul de l’établissement Inventaire permet d’analyser la tariﬁcation de dix articles vendus. La saisie d’une valeur en A15 rajoute automatiquement une ligne avec les formules de calcul adéquates en D15 (= RECHERCHE(C15 ; C$1 : F$1 ; C$2 : F$2)), F15 (= E15*D15), les colonnes D et F étant calculées. L’ajout d’une ligne de total permet de calculer le prix moyen en sélectionnant « moyenne » dans la liste.

Les tableaux croisés dynamiques (TCD)

Les caractéristiques du TCD
  • Comme son nom l’indique, le TCD présente trois caractéristiques essentielles :
    • Tableau : lignes et colonnes créées dans la même feuille que les données source ou dans une autre feuille du classeur ;
    • Croisé : multiplicité de critères pris en compte simultanément quand ils sont satisfaits ;
    • Dynamique : restitutions du TCD prenant en compte toutes les évolutions choisies par l’utilisateur (ex. : modiﬁcation des données ou des critères), tant dans les valeurs que dans les critères.
  • La synthèse est générée automatiquement par le TCD en fonction de critères choisis par l’utilisateur ; elle procède au dénombrement, à l’addition et autres opérateurs mathématiques des éléments du tableau de données d’origine satisfaisant simultanément tous les critères.

Définition

Le tableau croisé dynamique (TCD) est un tableau de synthèse construit à partir d’un tableau de données (tableau-source).

Le choix du TCD adapté
  • Dans le menu « Insertion », on dispose de trois possibilités de choix de fonctionnalités du tableau :
  • Sous-menu « tableaux croisés dynamiques ». Entièrement personnalisable, il est plus adapté pour choisir librement ses propres critères ;
  • Sous-menu « Tableaux croisés recommandés (TCR) ». Il possède des fonctionnalités de calcul multicritères dépassant le simple tableau, mais découle de suggestions initiales du tableur, ce qui rigidiﬁe l’ensemble et induit, le plus souvent, un travail important d’adaptation ;
  • Sous-menu « Tableau ». Il accomplit essentiellement des modiﬁcations d’afﬁchage. Aucun dénombrement n’est effectué sur les résultats d’afﬁchage obtenus. Les tris de valeurs sont successifs et s’appliquent à l’afﬁchage antérieur. Il est aisé de modiﬁer les ﬁltres conformément aux besoins d’afﬁchage identiﬁés. De nombreuses possibilités de choix (couleurs, graphiques, etc.) sont offertes.
Les étapes de construction du TCD
  • Il faut tout d’abord disposer d’une source de données et la sélectionner.

Les graphiques

Le choix et la création d’un graphique
  • Les tableurs disposent de fonctionnalités qui permettent de créer un graphique adapté au besoin de communication ou d’analyse et qui pourra évoluer. Ils permettent de visualiser les données et sont donc très utile en gestion ;
  • Les graphiques sont liés par des formules aux séries de données concernées générées automatiquement par les « outils graphiques » intégrés au tableur et disponibles dans le menu « Insertion » ; ils doivent être adaptés au contexte ;
  • Sélection des données source. Pour créer un graphique, il sufﬁt de sélectionner les données pertinentes, d’opter dans l’onglet « Insertion », pour un type et d’en visualiser l’aperçu, aﬁn de choisir le type le plus adapté (courbes, secteurs, histogrammes…), chacun disposant de plusieurs variantes.
  • Il faut sélectionner au moins une cellule dans une plage continue de données (toutes les données de la plage sont sélectionnées) ou sélectionner des plages ou des cellules non adjacentes (la sélection doit former un rectangle ou un carré) ;
  • Les données doivent, au préalable, avoir été organisées en fonction du graphique souhaité, avec la possibilité d’en masquer certaines ou d’utiliser des ﬁltres ;
  • Implantation. Le graphique est implanté dans la feuille active mais peut être déplacé en fonction des besoins dans une autre feuille (quel que soit son emplacement, il reste lié aux données source).

L’adaptation du graphique
  • Les outils de graphique permettent, une fois le graphique créé, d’agir sur de nombreuses fonctionnalités regroupées en trois sous-menus : création, disposition ou mise en forme ;
  • Le type peut être modiﬁé :
    • Soit en sélectionnant le graphique et en effectuant un clic droit ;
    • Soit à partir du sous-menu « Création de graphique », en optant pour « Modiﬁer le graphique ».
  • Le sous-menu « Style du graphique » regroupe les différents éléments sur lesquels on veut agir, également accessibles un à un par un clic droit en les sélectionnant sur le graphique.

Exemple

L’entreprise Yanna utilise, entre autres, la méthode du prix psychologique pour ﬁxer ses tarifs. Elle obtient un graphique pas tout à fait adapté et le modiﬁe en utilisant le menu « Disposition » et en insérant des zones de texte.

2.6.2 Les autres outils d’aide à la décision

Les macros

  • Pour automatiser une tâche répétitive, mettre en place des mécanismes de contrôle et actualiser des données, il est possible d’enregistrer une macro-commande ou macro, c’est-à-dire une séquence d’actions automatisant une tâche dans le langage de programmation Visual Basic pour Applications (VBA) ;
  • Toute macro peut être affectée à un objet (dessin, bouton, graphique, contrôle…) ou à un raccourci clavier ce qui en facilite l’exécution. Une fois exécutée, une macro ne peut être annulée ;
  • La suite de tâches peut être également créée à l’aide de Visual Basic Editor, ouvrant alors le champ à la gestion de d’algorithmes, de formulaires et d’événements ;
  • Si l’onglet « Développeur » ne s’afﬁche pas, il convient de l’activer à partir de « Fichier/Options/Personnaliser le ruban » en cochant la case.

A savoir

Pour limiter l’exécution de codes potentiellement dangereux, vous pouvez désactiver les macros dans les paramètres de sécurité.

L’enregistrement des macros
  • L’enregistreur de macro est accessible à partir de l’onglet « Développeur » du menu « Fichier/Options/Personnaliser le ruban » :
  • Cet enregistreur mémorise toutes les étapes permettant d’effectuer les actions que devra exécuter la macro nommée de façon explicite, les tâches enregistrées pouvant concerner d’autres progiciels (Word, Access…) ;
  • Une macro est le plus souvent enregistrée pour un classeur, mais il est possible de créer un classeur de macros personnelles, ces dernières étant mobilisables dans plusieurs classeurs ;
  • La macro s’exécute uniquement dans les cellules des plages sur lesquelles on a effectué l’enregistrement ;
  • Si cette plage est modiﬁée (ex. : ajout d’une ligne), il faut modiﬁer la macro en conséquence dans l’éditeur ;
  • Lorsque la série de tâches à enregistrer est très longue, il vaut mieux enregistrer plusieurs macros courtes et arrêter l’enregistrement après la dernière action ;
  • Une visualisation rapide de la macro, dans l’éditeur, permet de repérer les erreurs (manipulation malencontreuse…) et de les corriger ;
  • L’onglet « Développeur » permet également de visualiser ou d’exécuter, éventuellement en mode pas-à-pas, les macros préalablement implantées.

A savoir

N’hésitez pas à documenter la macro par une description pour faciliter les échanges au sein de votre équipe projet et aider les futurs utilisateurs de la macro.

L’écriture en VBA
  • L’éditeur VBA est accessible par le menu « Développeur » ou par le raccourci Alt+F11 ;
  • La macro sera écrite dans un module qui peut en contenir plusieurs ;
  • Le code peut être écrit ou recopié (copier/coller) à partir d’une autre macro ou d’un document d’Ofﬁce ;
  • L’éditeur facilite l’écriture, le contrôle et le débogage du programme en VBA ;
  • Pour les programmes complexes, l’écriture sera bien sûr précédée d’un travail de conception intégrant un algorithme ;
  • Les macros peuvent ensuite être modiﬁées ou supprimées.

2.6.3 L’audit d’une feuille de calcul

Les outils d’audit du tableur

  • Une formule retourne parfois une erreur inexpliquée ce qui fausse le résultat ;
  • Des outils d’audit de formules permettent de rechercher et/ou de corriger les causes d’erreur difﬁciles à expliquer :
    • Lors de la saisie, les erreurs les plus courantes sont annoncées ;
    • Après la saisie, un triangle s’afﬁche dans le coin supérieur gauche de la cellule quand une erreur ou une incohérence est détectée ; Excel propose alors des options pour corriger ou ignorer l’erreur ;
  • Il est également possible d’utiliser l’audit de formules (menu « Formules ») :
  • L’icône ci-dessus permet d’afﬁcher les formules et d’identiﬁer rapidement les erreurs les plus évidentes ;
  • La fenêtre « espion » permet de visualiser une formule et son résultat, ce qui facilite l’audit dans les grandes feuilles de calcul ;
  • La boîte de dialogue « Évaluation de formule » permet de visualiser pas-à-pas les différentes parties d’une formule imbriquée ;
  • La boîte de dialogue « Vériﬁcation des erreurs » permet de vériﬁer ou de repérer les erreurs et de repérer ou de résoudre les références circulaires ;
  • Pour tracer le suivi des relations entre les formules et les cellules à l’aide de ﬂèches d’audit, il convient d’utiliser les fonctionnalités « Repérer les antécédents » ou « Repérer les dépendants » :
  • Les ﬂèches rouges matérialisent le suivi des erreurs ; les ﬂèches en pointillés noirs reliées à un symbole de « feuille », les relations entre feuilles ou entre classeurs ; les ﬂèches bleues, les références sans erreur ;
  • La cohérence des données ou des formules peut également être contrôlée par des fonctions « SI », combinées à des fonctions d’information ou par le recours aux outils de validation des données ;
  • Les options de ﬁchier (Fichier/Options/Formules) permettent d’activer (ou de désactiver) certaines règles de vériﬁcation des erreurs :

Les outils de sécurité du tableur

  • Excel offre plusieurs niveaux de protection en fonction des besoins de gestion et de l’analyse des risques ;
  • Ils permettent de préserver le travail du concepteur du modèle implanté, mais également de sécuriser les données, voire d’en assurer la conﬁdentialité.
La protection de la feuille
  • Pour préserver le contenu des cellules d’une opération malencontreuse (suppression d’éléments, modiﬁcation de formules…) ou en contrôler l’utilisation, il est possible de protéger cette cellule :
    • Par défaut Excel verrouille toutes les cellules (menu « Accueil / Format de cellules, Protection ») ;
    • Pour maintenir l’accès à certaines cellules, il convient donc de modiﬁer ce verrouillage avant d’activer la protection (menu « Révision / Protéger la feuille »), et de choisir un mot de passe. Il est possible d’autoriser la modiﬁcation de plages, éventuellement par un mot de passe, lorsque la protection est activée. Ces actions sont accessibles à partir de l’onglet « Révision » ;

2.7.3 Les fonctions et les procédures

Les fonctions

Définition

Une fonction est un programme exécutant une suite d’instructions et renvoyant une valeur.

  • Une fonction peut être :
    • Utilisée dans un autre programme, par une autre fonction ou en tant qu’élément d’une expression (il s’agit donc d’un sous-programme) ;
    • Mobilisée dans une feuille Excel pour compléter les fonctions (standard) prédéﬁnies par le progiciel (environ 300).

A savoir

N’hésitez pas à consulter l’aide en ligne du tableur pour trouver la fonction standard dont vous avez besoin.

  • Il est possible de créer des fonctions personnalisées avec VBA ;

La procédure

Définition

Une procédure (Sub) est également un programme (suite d’instructions), exécuté par un utilisateur ou appelé dans une autre procédure mais ne renvoyant pas de valeur.

  • Une procédure effectue une suite d’actions ;
  • Par défaut, une procédure est publique et donc accessible depuis tous les modules ;
  • Si l’on désire qu’une procédure soit accessible uniquement dans un module, il faut le préciser en démarrant la procédure avec : Private Sub Nom_Procédure () ;

A savoir

Il est parfois utile de rédiger une fonction VBA personnalisée plutôt que de rédiger une formule Excel avec imbrications de « SI » combinant de multiples conditions. Si les conditions évoluent, il est plus aisé de les modiﬁer dans le programme. Le risque de générer des erreurs sera minimisé.
